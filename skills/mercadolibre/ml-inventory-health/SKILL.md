# 美客多库存健康检查

## 目标
监控美客多 FULL 仓库和自发货的库存水平，识别断货风险 SKU、滞销库存和超库容预警，输出补货建议。

## 触发生效条件
- 用户询问「库存情况」「哪些快断货了」
- 用户要求「检查滞销品」
- 用户需要「补货建议」
- 定时任务触发（如每日 09:00）

## 执行流程

### 步骤 1：获取库存数据
```bash
ziniao-cli page visit --store-id <ID> --url "<库存管理页面>" --wait-until networkidle
ziniao-cli page extract --store-id <ID> --mode page --format json
```
对于 FULL 仓库和自发货分别提取：
- SKU 名称
- 当前库存量
- 在途数量（如适用）
- 近 30 天日均销量
- 最低库存阈值

### 步骤 2：计算可售天数
对每个 SKU 计算 `可售天数 = 当前库存 / 日均销量`。
分类标记：
| 可售天数 | 标记 | 说明 |
|----------|------|------|
| < 7 天 | 🔴 紧急补货 | 即将断货，立即安排 |
| 7-30 天 | 🟡 正常库存 | 近期需安排补货 |
| 30-90 天 | 🟢 库存充足 | 可持续销售 |
| > 90 天 | ⚪ 滞销 | 考虑促销或清理 |

### 步骤 3：补货建议
对于标记为紧急和正常的 SKU，计算建议补货量：
```
建议补货量 = (海运周期天数 + 安全库存天数) × 日均销量 - 当前库存 - 在途
```
考虑因素：
- 目标站点到中国的海运周期
- 季节性需求波动
- FULL 仓库库容限制

### 步骤 4：超库容预警
检查 FULL 仓库当前使用率 vs 分配限额。
如库容使用率 > 90%，发出预警。

### 步骤 5：输出库存健康报告
```markdown
# 库存健康报告
站点/店铺: 墨西哥站 | 日期: YYYY-MM-DD

## 紧急补货（可售天数 < 7）
| SKU | 库存 | 日均销量 | 可售天数 | 建议补货 |
|-----|------|----------|----------|----------|
| — | — | — | — | — |

## 滞销库存（可售天数 > 90）
| SKU | 库存 | 日均销量 | 存放天数 | 建议 |
|-----|------|----------|----------|------|
| — | — | — | — | 促销/降价 |

## 库容情况
已用: XX% | 限额: NNN
```

## 失败处理
| 错误 | 处理 |
|------|------|
| 库存页无数据 | 提示用户检查 FULL 使用状态 |
| 某 SKU 无销量历史 | 新品标记为「无数据」，建议手动设定补货参数 |
| 库存量显示异常（超过物理容量） | 以系统显示为准，标注异常 |

## 注意事项
- 本技能数据来自卖家后台库存页面，与真实物理库存可能存在延迟
- 补货建议基于历史销量估算，实际需结合供应链实际情况调整
- 滞销品建议处理：降价促销 → 捆绑销售 → 撤仓转为自发货
